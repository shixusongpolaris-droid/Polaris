# 多房间扩展（feat/multi-room）

> 基线：单房间冻结版 `v1.0-single-room-freeze`（`36ff8e8` / `6343ec1`）
> 本目录是**新项目/加分项**，不改动冻结版结论；失败就回退到冻结版。
> 当前状态：**设计 / 骨架**，尚未实现、未训练。

## 一、目标

在 2 房间（A 实测房间 + B 扰动房间）的设定下，回答：

1. 多房间的**协调间隙**有多大——独立房间规则 vs 协调规则/MPC，差多少？
2. 如果间隙足够大，RL 能否超过**独立规则**？能否超过**协调规则/MPC**？
3. 如果能，多房间是否给 RL 带来单房间没有的结构性优势；如果不能，边界结论是否更稳？

**不预设答案。** 多房间给的是更大的策略空间，不是自动胜利。

## 二、范围（2 房间 MVP）

- **房间 A**：沿用单房间实测参数（`src/env/config.py` 的 `SimConfig`）。
- **房间 B**：同参数 + UA/gain ±20% 扰动；标注“合成房间”，不声称实测。
- **耦合**：共享墙 + 一扇门；门开时房间间传热系数大，门关时小。
- **占用**：一人三态（A / B / 外出）。A 无人时按概率分到 B 或外出；A 的时长池沿用实测。
- **空调**：每房间一台；共享电价；可加全屋总功率上限。
- **动作**：`MultiDiscrete([8,3,2] × 2)`（2 房间）；用 SB3 PPO 的 MultiDiscrete。
- **观测**：每房间温度/湿度/光照/占用/AC 状态 + 门状态 + 共享电价/天气；约 50~60 维。
- **奖励**：按房间占用加权的舒适 + 全屋电费 + 切换；可加公平性/总功率。
- **约束**：每房间 C1~C4；门状态；总功率上限。
- **评估**：8 回合 × 10 种子；held-out；每房间 + 全屋指标。

## 三、分阶段（先做门槛，再投入）

### Phase 0：协调间隙诊断（2~3 天，不训练 RL）

- 实现 2 房间环境；
- 只比较：
  1. 独立房间规则（每房间各跑单房间最优规则）；
  2. 协调规则（按占用/门状态预冷、关空闲房间、总功率分配）；
  3. 恒温全开/全关；
- 输出：全屋电费、每房间不达标率、协调规则相对独立规则的改善。

**Go / No-Go**：

- 协调间隙小（例如 <5%）→ 多房间没有多少协调空间，RL 大概率也难有结构性优势；**停，写“未来工作”**。
- 协调间隙大（例如 >15~20%）→ 继续 Phase 1。

### Phase 1：2 房间环境 + 测试（2~4 天）

- 多区热网络、门状态、MultiDiscrete、每房间 C3/C4；
- 单元测试：热平衡、门传热、占用切换、动作映射、C3/C4；
- `test_env` 扩展：2 房间版自检。

### Phase 2：基线 + 训练（1~2 周）

- 独立房间规则、协调规则/MPC、恒温全开；
- PPO（MultiDiscrete），10 种子；
- 先跑单种子 smoke，再全量。

### Phase 3：盲评 + 复现（1 周）

- 独立审计：强协调基线、held-out、逐位复现；
- 只有通过审计，才写“RL 超过协调基线”；否则写“RL 只超过朴素规则”。

## 四、目录规划

```
multiroom/
  README.md          # 本文件
  src/               # 多区环境（不修改冻结版 src/env）
  scripts/           # 训练/评估/诊断
  models/            # 多房间模型（不提交大文件，按需）
  docs/              # 设计/审计/结果
```

**硬约束**：

- 不修改冻结版 `src/env`、`scripts/`、`models/freeze_36ff8e8/`、`docs/单房间最终结论_冻结模型.md`；
- 多区环境放在 `multiroom/src/`，可 `import src.env` 复用配置/动作，但不得改变单房间行为；
- 所有结果标注“合成多区（B 房间未实测）”；
- 基线必须独立构造，不能为了“让 RL 赢”弱化协调规则/MPC；
- 失败/超时：直接回退到冻结版 `v1.0-single-room-freeze`。
