## 三、多房间的目标与原则

目标：回答“多房间是否给 RL 结构性优势”，而不是“让 RL 赢”。

1. **Phase 0（先做）**：2 房间环境 + 协调间隙诊断，不训练 RL。
   - 独立房间规则 vs 协调规则（oracle）vs 恒温全开；
   - 看协调规则相对独立规则改善多少；
   - 间隙小 → 停，写“未来工作”；间隙大 → 继续。
2. **Phase 1**：2 房间环境测试（热平衡、门传热、占用、C3/C4）。
3. **Phase 2**：基线 + PPO（MultiDiscrete）。
4. **Phase 3**：盲评/复现。

**硬约束**：

- 不修改冻结版 `src/env`、`scripts/`、`models/freeze_36ff8e8/`、最终结论；
- 多区环境在 `multiroom/src/`，可 import 冻结配置，但不改变单房间行为；
- B 房间没有实测，所有结果标注“合成多区”；
- 协调规则/MPC 必须独立构造，不能为了 RL 赢而弱化；
- 结果要么作为结题附录，要么写“未来工作”。

## 四、Phase 0 的 Go / No-Go

- **停**：协调规则相对独立规则的不舒适改善 <1pp，或成本增加 >15% 换取很小改善；
- **继续**：协调规则显著降低不舒适（例如 ≥1pp），且成本增加可接受（例如 ≤10%）。

这只是门槛，不是最终结论；Phase 0 用合成周，B 房间未实测。

**当前边界结论**：合成 2 房间 + 300k/1M 预算下，**强协调规则（coord15/45）仍支配 PPO**；
多房间的协调价值可以被简单规则捕获，RL 没有表现出额外结构性优势。
这与单房间“规则至少不输”的结论一致；不能外推到真实多房间。

**Phase 0 结论**：协调间隙是真实的（7.14%→0%），但**不是免费的**：
15 分钟预冷可把不舒适减半（+9.7% 电费），45 分钟才能归零（+23.1%）。
所以 RL 的对手不是“独立规则”，而是 **coordinated 15/45min 这个强基线**；
如果 RL 只能赢独立规则、赢不了这个强基线，结论仍是“RL 只优于朴素规则”。
