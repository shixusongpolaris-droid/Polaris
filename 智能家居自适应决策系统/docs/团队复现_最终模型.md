- C3 在这四组中触发步数均为 **0**（23~29°C 全程处于 16~30 安全区间），不影响能耗口径。

### 3.2 公式独立重算

按 `simulator.py` 文档公式逐帧重算（不调用脚本的检查 7）：

```
cooling_kw = capacity × gross / ac_max_cooling      (capacity=3.5, ac_max=2.1175)
p_comp     = min(cooling_kw / COP, rated_kw)        (COP=3.0, rated=1.1)
p_ac       = p_comp + ac_fan_kw                     (fan=0.04)
e_step     = (p_ac + p_light + p_vent) × 0.25h + startup(仅当 gross>0 的启动)
```

四组总电量与 `sim.metrics["total_energy_kwh"]` 差 **0.00e+00**（含启动损耗）。说明上报电量严格等于"15 分钟平均功率 = cooling/COP"。

### 3.3 低负荷有效 COP 不再被 0.20 底价拉低

| 设定 | 新模型有效 COP 最小值 | 旧 0.20 底价模型有效 COP 最小值 |
|---|---|---|
| 23°C | **3.0000** | 0.2898 |
| 25°C | **3.0000** | 0.0211 |
| 27°C | **3.0000** | 0.2087 |
| 29°C | **3.0000** | **0.0781** |

- 新模型：只要有制冷，`COP_eff = cooling/(cooling/COP) = 3.0`（仅在冷却量 > 额定功率×COP 时被额定功率截断，此时 COP_eff ≥ 3.0）。**低负荷不再有任何底价。**
- 旧模型：底价在 29°C 有 154/672 步生效，最低有效 COP **0.078**——与审计/提交说明的“可至 0.075”同量级（25°C 甚至低到 0.021）。
- 具体一步（29°C）：`gross=0.0122°C/步 → cooling=0.0202 kW`；新 `p=0.0067 kW`（COP=3.00），旧 `p=0.2200 kW`；本步电量 **0.01168 vs 0.06500 kWh**（旧模型是 5.6 倍）。
- 旧底价版本多收：25°C **0.983**、27°C **0.475**、29°C **0.638** kWh/天，落在提交说明的 **0.47~0.98** 区间内（另 23°C 多收 0.339，说明未列，不矛盾）。

## 9. 发现与建议（均不影响“修复有效”）

**F1（信息，口径）C3 的“30°C 上限”是步首约束，不是观测温度的硬上限。**
C3 在每步**开始**用 `state.temp_in` 判断；本步内若制冷能力不足/负荷大，温度仍可继续上升。实测：C3 触发的 12 步动作前温度 30.002~30.293°C，而 run 内最高观测温度 30.24~30.29°C（test_env 检查 2 也记录到 30.28）。若文档表述为“室内温度不超过 30°C”，应改成“每 15 分钟决策点不超过 30°C（步内最大观测约 30.3°C）”。

**F2（信息，计数口径）C3 的 12 步必须从“无人但开机”统计里单列。**
hard 模式：176 步无人≥30min 中，0 步 C4 违规 + 12 步 C3 安全例外；precool：0 坏例 + 53 允许预冷 + 12 C3。也就是说，默认 precool 下“无人仍开机”共 65 步（53 设计允许 + 12 安全），任何下游分析若直接数“无人开机”会把这 12 步误判为违规。

**F3（低，测试覆盖）test_env 场景 A 现在关闭 C4/C3，只测 C1/C2；`interval > dt` 的 C4 强制关机没有进 test_env。**
S2b 的修复（强制关机不受间隔约束）目前只有本报告的独立脚本覆盖。建议在 `check_constraints` 加一个“`interval=60` + hard”的小场景（约 672 步，几秒），否则将来有人改回“强制关机也受间隔约束”时 test_env 不会报警。

**F4（低，指标细节）C3 覆盖时 `ac_blocked` 被清零。**
`simulator.py` 在 `c3_override` 时把 `ac_blocked=False`，因此“C4 刚想强制关机、随后被 C3 反转”的这一步不会被计入 `ac_blocked_count`。语义上合理（最终动作是安全动作，不是被屏蔽），但若有人用 `ac_blocked_count` 衡量 C4 覆盖强度，会低估。建议在文档注明或把 `c3_override_count` 与 `ac_blocked_count` 并列解读。

## 10. 限制

- 本报告只验证“实现与提交说明一致、内部自洽、可复现”；未评估 `ac_cop=3.0`、`ac_fan_kw=0.04`、`ac_max_cooling`、`temp_safe` 等参数的实测可信度（属独立标定/盲评任务）。
- C3 的“安全”只覆盖温度区间 16~30°C，未涉及湿度/空气质量等其他安全维度。
- 未训练任何模型；S3 工具只验证了代码路径与输出文件，未验证真实训练/评估数字（提交本身也不含新实验结论）。
- t3/t4 的 628/305 行报告（规则前沿、selection bias）、六格电价与 30 个模型需在新模型下重跑，本报告不涉及。
