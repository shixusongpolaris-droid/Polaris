## 1. 方法：五个环境变体与"尺子"校准

### 1.1 变体设计（为什么需要五个）

`e9e5bb1` 同时改了三件事：**S1b 能量公式**（去掉最低功率平均底价、启动损耗仅 gross>0）、
**C3 安全区间**（T>30 强制最低档、T<16 强制关机、优先于 C4）、**C4 强制关机不受最小切换间隔约束**。
只比 "539561e vs e9e5bb1" 会把三者混在一起，所以拆成：

| 变体 | 代码 | C4 | C3 | 用途 |
|---|---|---|---|---|
| `old` | `ce731b5` 原样 | 旧（只在动作变化时检查） | 无 | 尺子基准 / "旧世界" |
| `final_energy` | `ce731b5` + **只在内存中**替换为最终能耗公式 | 旧 | 无 | **纯能量口径**（行为逐位不变） |
| `final_noc4_noc3` | `HEAD` + `c4_mode="off"` + `c3_enforce=False` | 无 | 无 | 隔离 S1b/S9b 的其余改动 |
| `final_c3off` | `HEAD` + `c3_enforce=False`（C4 默认 precool） | 新 | 无 | **隔离 C3** |
| `final` | `HEAD` 默认（C3 开 + C4 precool） | 新 | 开 | **交付的最终模型** |

`final_energy` 的做法（`harness.patch_energy(mode="final")`，只在分析进程内生效、不改仓库任何文件）：
用与旧实现逐字相同的热更新先算出空调本步的 **gross cooling**
（`min(max(ac_coef·(T−T_set), 0), ac_max_cooling)`），再按
`P_comp = min(cooling_kw/COP, 额定功率)`（**无**最低功率平均底价）、`P_ac = P_comp + 0.04 kW 风机`、
启动损耗只在 `gross>0` 时计。温度状态量完全不动。

**验证**：`old` vs `final_energy` 在 941 条规则上有人不达标率最大差 **0.0e+00**、有人均温最大差 **0.0e+00**、
C4 改写占比最大差 **0.0e+00**。所以这一对之间**只有计费口径**一个变化。

> 另一个坑：`final_noc4_noc3` 与 `old` 只有 **14/941** 条不达标率相同（最大差 11.80 个百分点），
> 差异来自旧 C4 的偶发强制关机（关掉 C4 后预冷才真正发生）。**不能用它当纯能量口径对照。**

### 1.2 统一协议 = t1_tou（沿用 t3 的结论并复核）

`gen7_unified/results.json`（`rew()` 默认价）的前沿与我的 t1_tou 前沿逐条一致（t3 已核到 0.0e+00）：
`RewardConfig(tou_enabled=True)` 且未设 `peak_periods/valley_periods` 时，`get_price()` 回落到
`peak_hours=(6,22)`、`valley_hours=(22,6)`，即峰/平 0.617、谷 0.307 —— 与 t1_tou 相同。
`energy_scale`（统一协议 10、六格 30）只进奖励，不影响评估指标。

### 1.3 指标与额外记录

每次评估 = 8 个回合（9100~9107）。energy = 每回合 `energy_per_day_kwh` 的均值；
cost = `Σ(实际电价 × 本步电量) / 天数` 的 8 回合均值；occ_discomfort = 有人且越界步数 / 有人步数；
另外记录：有人/无人分项电量、空调开机率、最高室温、`T>30°C` 步占比、
C3 改写步占比（`info["c3_override"]`）、C4 阻断步占比（`info["ac_blocked"]`）。

**答案：被改变了，但方向是"更安全、更贵一点"，不是"结构重排"。**
具体：

1. 高不舒适端的最左点从 **31.34% 降到 30.77%**（C3 把"靠热换便宜"的空间压小了），
   该点电费从 2.781（c3off）升到 2.950（+6.1%）。
2. 高不舒适端整体电费上移：便宜的 51.7% 端 1.543→1.717（+11.3%），贵的 30.8% 端 2.781→2.950（+6.1%）。

## 10. 局限与未做

1. **未重训任何模型**（任务约束）。"最终模型下 RL 是否更强"这个问题**没有回答**；
   §5/§6 只是"旧策略在新计价下的位置"。
2. **未重评 `models/gen7_vecnorm_confirm/` 的 40 个模型与 energy_scale 扫描**，旧四行 Welch t 悬空。
3. **C4 只评了默认 `precool` 与 `off`**；`hard` 模式、`c4_precool_threshold`（0.02）、
   `ac_auto_off_empty`（30 min）、C3 的 `temp_safe_max`（30°C）都没做敏感性。
   C3 的强制档固定 23°C，落在睡眠舒适带 24~27°C 下界之外，是一个潜在隐患
   （对 `全开 26°C` 我核到的差异全部在白天，所以这不是唯一来源；未逐条归因）。
4. **`final_energy` 是分析进程内的 monkeypatch**（不改仓库），用于隔离"纯计费口径"；
   若要把该口径做成正式对照，应在 `src/` 里参数化（例如 `energy_basis="gross_cycle"`）。
5. **8 回合的统计力有限**：六格 Welch t 的 df≈7，双侧 5% 临界 2.365；
   ±5% 以内的差值（t1_flat −3.8%、t3_flat −0.8%、t3_tou +2.4%）不应解读为实质差异。
6. **C3 与 C4 的交互未做机制级分析**：C3 安全优先于 C4，导致无人超时 + T>30 时仍强制制冷，
   与 C4 形成"关—开—关"交替（C3 改写步占比 1.02%）。这部分对电费的影响已计入本文件中，
   但没有单独的消融实验去量化"交替次数 × 启停损耗"。
