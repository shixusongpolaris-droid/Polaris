## 六、为什么这次能复现：风险点排查

复现链条的每一环都查过，结论是"不依赖外部状态"：

1. **随机性来源**：四个脚本都用固定种子（A/D 用 9100+ep，B 用 100000+ep，C 用 1000 且实为强制驱动），
   仿真起点固定为 `datetime(2026, 1, 5)`，没有使用 `datetime.now()` 参与状态转移（只有文档里的"生成时间"用它）。
2. **数据文件**：`data/processed/timeline_final.csv`（10-17 06:03）、`outdoor_temp_backfill.csv`（10-17 01:28）、
   `data/raw/*.csv`（10-16）在四个结果生成之后均未再改动，重跑读到的输入与当时相同。
3. **源码**：`src/env/config.py`（08:14）、`src/env/simulator.py`（08:49）在 A/B/D 生成之前已定稿，未再改动；
   C 早于它们，但如上节所述其口径不受影响。
4. **工作区未提交改动**：`src/env/reward.py` 在 **21:25:37** 有一处未提交修改
   （"无人时不施加趋中心梯度"：区间内且无人时 `temp_cost` 返回 `(0.0, 0.0)`）。
   它晚于 A（20:51）、B（10:05）、C（08:13）、D（21:21）四个结果。
   本次重跑是在**带着该修改**的工作区里进行的，四个结果仍逐字节相同 ——
   这同时证明该修改对这四个实验的指标是**惰性**的：
   `temp_dev`（`discomfort_ratio`/`temp_dev_rmse`/D 的桶计数都基于它）在"区间内"分支上改前改后都是 0.0，
   能耗项与策略行为则完全不读奖励函数。
5. **不涉及训练**：D 的 RL 模型是磁盘上的 `.zip` 权重（`energy_scale_ci/es*_s42`），本次只做前向推理，
   `PPO.load(..., deterministic=True)`。训练类结果的可复现性不在本任务范围（重训必然受硬件/线程/版本影响）。

**风险提示（不属于这四次实验的失败）**：只要结果是在 08:57（启动损耗修复）之前生成的能耗类数字，
在当前代码下就无法复现；若将来再改 `config.py` / `simulator.py`，A/B/D 会立即失去这种逐字节复现性。
建议把"结果 JSON 里记录源码版本 + 数据文件哈希"固化进脚本，这一点目前没有做。

## 八、局限

- 只验证了"同机、同解释器、同依赖版本、同一份数据"下的可复现性。跨机器 / 跨 BLAS / 跨 numpy 版本未验证；
