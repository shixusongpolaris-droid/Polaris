### A2. 为什么必须 ÷4 —— 通过（已用单步手算证实）

`config.py:70-82` 的注释说明"本仿真中 `dT` 直接加到温度上、不乘 dt，因此系数是每步量"，而联合拟合用每小时速率并乘 `dt=0.25`。

- 读代码：`simulator._update_temperature`（`simulator.py:362-408`）确实是 `dT = -ua*(T-Tout) + gain_base + solar - cooling ...`，最后 `T_new = T + dT`，**没有乘 dt**；`joint_fit_thermal.py:198-206` 是 `pred.append(T + dT*dt)`，**乘了 dt**。
- 实测验证：我在同一初始状态下手算多项式并与 `env.step()` 对比，`差 = 0.000e+00`（`gen6_AB.py` A2 段）；若误乘 dt=0.25 会差 1.84 °C。
- 所以"拟合值 ÷ 4"**正确**。

### A4【高】"当前参数 RMSE 4.6138" 是错的，真实的收敛改善只有 0.17%

这是本轮最需要纠正的一条。`scripts/joint_fit_thermal.py:236-237`：

```python
r_cur = rmse(series, [cur.ua_coef, 0.0, cur.internal_gain, 0.0,
                      cur.ac_coef, cur.ac_max_cooling])
```

`rmse()`/`simulate()` 里的 dT 是 **°C/小时**、最后乘 `dt=0.25`；而 `cur.ua_coef`/`cur.ac_coef` 是**每步**值。这里把每步值直接当每小时用，**动力学慢了 4 倍**；同时还把 `gain_base`、`solar_coef` 置 0。两者叠加，得到 `docs/全时段联合标定.md:59` 的"当前参数为 **4.6138 °C**"。

我把单位换算补正后重算同一序列（`gen6_A4b.py`，200 步、6 段空调、占用 132 步）：

| 口径 | RMSE |
|---|---|
| 脚本现在的 `r_cur`（每步值当每小时 + gain_base/solar=0） | **4.6138** ← 文档用的 |
| gen5 参数、gain_base/solar 置 0、但正确 ×4 | 4.8445 |
| **gen5 实际配置**（0.1383/0.76/0.23/2.0125/2.1475，×4） | **1.7821** |
| **gen6 实际配置**（当前 config，×4） | **1.7790** |
| 联合标定 fitted | 1.7790 |

所以：

- 文档的"1.7790 vs 4.6138"把改善夸大成 **−61%**，真实是 **1.7821 → 1.7790 = −0.17%**（拟合质量几乎没变）。
- commit 里的"全时段 RMSE 1.8876 → 1.7790"也不可比：1.8876 是 **gen5 在 5 段数据上**的拟合 RMSE，1.7790 是 **gen6 在 6 段数据上**的拟合 RMSE，数据集不同；在同一份 6 段数据上，gen5 参数 1.7821、gen6 参数 1.7790。
- 由此产生一个更需要警惕的推论：**参数值变了 1.4%~17.4%、拟合质量只提高 0.17%，但下游实验的电量最多变了 32.8%**（见 D1）。这说明参数**可辨识性差、结果对参数高度敏感**，不能只用"RMSE 更小"当作 gen6 更可信的依据。

附带（同一函数）：

- `joint_fit_thermal.py:289,369` 与 `docs/全时段联合标定.md:63` 写"最大制冷 **8.47 °C/步 = 33.9 °C/小时**"——**单位标反了**。模型里 `ac_m` 是 °C/小时（8.47），正确写法是"8.47 °C/小时 = **2.12 °C/步**"。commit 自己的表（8.47/小时 = 2.1175/步）是对的，文档是错的。
