## 一、标定前后的参数与行为

### 1.1 参数变更

| 参数 | 修正前 | 修正后 | 依据 |
|---|---|---|---|
| `temp_outdoor_mean` | 30.0 °C | **22.0 °C** | 实测室外 18.8~25.8 °C，均值 22.0 °C（10 月上海闵行） |
| `temp_outdoor_swing` | 5.0 °C | **3.0 °C** | 实测日内波动约 ±3 °C |
| `ua_coef` | 0.040 | **0.115** | 由实测时间常数 τ ≈ 130 分钟反推（τ = dt/ua_coef） |
| `internal_gain` | 0.02 | **0.80** | 由实测稳态偏移 +7 °C 反推（偏移 = internal_gain/ua_coef） |

**未改动的参数**：`ac_coef`、`ac_max_cooling`、`vent_coef`、湿度模型参数。
理由：实测制冷速率给出的是**上界**（降温最快的瞬态段），
而原参数已有基于稳态分析的取值依据；在缺少空调功率数据的情况下，
不具备充分证据推翻原值。

### 1.2 仿真行为对比（随机策略、一个回合 = 7 天）

| 指标 | 修正前 | 修正后 | 实测真值 |
|---|---|---|---|
| 温度范围 | 25.2 ~ **33.9** °C | **21.8 ~ 28.2** °C | 19.3 ~ 31.0 °C |
| **温度均值** | **28.05** °C | **24.63** °C | **约 24.5** °C |
| 均值误差 | **+3.55** °C | **+0.13** °C | — |
| 温度标准差 | 2.21 °C | 1.42 °C | 空调循环下约 2 °C |
| 空调开启占比 | 63% | 64% | — |

**修正后温度均值与实测几乎一致（差 0.13 °C），修正前偏高 3.55 °C。**

## 二、推导过程

仿真温控方程（`src/env/simulator.py::_update_temperature`）：

```python
dT = -ua_coef * (T - T_out)          # 围护结构传热
if ac_on:  dT -= min(ac_coef*(T - setpoint), ac_max_cooling)
if vent:   dT -= vent_coef * (T - T_out)
if occ:    dT += internal_gain
```

这是按步长 `dt = 15` 分钟离散化的形式，等价于连续一阶系统：

```
dT/dt = (T_out - T)/tau + G       其中 tau = dt/ua_coef
```

因此有两个可直接从实测读取的关系：

| 关系 | 表达式 | 实测值 |
|---|---|---|
| 时间常数 | `tau = dt / ua_coef` | 空调关闭后趋近平衡的时间尺度 |
| 稳态偏移 | `T_inf - T_out = internal_gain / ua_coef` | 无人、无日照时的室内外温差 |

### 2.1 实测得到的关键量

| 量 | 实测 | 来源 |
|---|---|---|
| 室外温度均值 | 22.0 °C | 10-15、10-16 的 Open-Meteo 数据 |
| 室外温度范围 | 18.8 ~ 25.8 °C | 同上 |
| 无人无日照稳态偏移 | **约 +7 °C** | 10-15 夜间室内 28.4 °C / 室外约 21 °C |
| 空调关闭后升温速率 | 5.5 ~ 10.2 °C/小时 | 5 个关空调事件的初始斜率 |
| 空调制冷最快速率 | −14.9 °C/小时 | 10-14 16:26~16:42 |

### 2.2 解出参数

```
取 tau ≈ 130 分钟：
    ua_coef = dt / tau = 15 / 130 ≈ 0.115

取稳态偏移 ≈ +7 °C：
    internal_gain = 偏移 × ua_coef = 7 × 0.115 ≈ 0.80
```

**验证**：`internal_gain/ua_coef = 0.80/0.115 = 6.96 °C`，
与实测偏移 +6~7 °C 吻合。

## 四、残留误差与模型局限（如实说明）

### 4.1 三个窗口的升温速率对比

| 窗口 | 实测升温 | 仿真预测 | 比值 |
|---|---|---|---|
| 夜间 | 1.74 °C/h | 1.45 °C/h | 1.20 |
| 凌晨 | **0.40** °C/h | 3.29 °C/h | **0.12** |
| 下午 | **0.39** °C/h | 1.81 °C/h | **0.21** |

### 4.2 问题所在

**实测房间在外界条件变化时温度几乎不动（仅 0.4 °C/h），比一阶模型预测慢 5~8 倍。**

这说明真实房间有明显的"环境钳制"效应：单一时间常数的单室模型
无法同时解释这三个窗口。可能原因：

| 原因 | 说明 |
|---|---|
| 围护结构热惯性 | 墙体蓄热使室内空气温度变化被显著缓冲，需"空气 + 墙体"两阶模型 |
| 太阳得热时变 | 日照强度随时间变化，而模型把它当作常数增益 |
| 相邻空间耦合 | 房间与客厅（实测 26.0 °C）之间有热交换，模型未建模 |
| 空调循环 | 空调启停导致温度被反复拉回，掩盖自由响应 |

### 4.3 为什么仍采用当前参数

尽管存在上述局限，修正后的参数在**最关键的指标（温度均值）**上
与实测从相差 3.55 °C 收敛到 0.13 °C，且温度范围、标准差都落在
实测区间附近。这对强化学习训练环境的真实性是实质性改善。

**进一步的模型改进需要结构变更（两阶热模型 + 日照时变输入），
属于后续工作。**

## 五、建议的后续改进

| 优先级 | 改进 | 预期收益 |
|---|---|---|
| 高 | 改为"空气 + 墙体"两阶热模型 | 消除 5~8 倍的速率偏差 |
| 高 | 日照得热作为时变外部输入 | 修正下午窗口的+2°C 高估 |
| 中 | 把客厅温度作为第二环境节点 | 解释门开时的热交换 |
| 中 | 实测空调型号与功率 | 精确标定 `ac_max_cooling` |
| 低 | 延长采集天数 | 提高统计显著性 |
