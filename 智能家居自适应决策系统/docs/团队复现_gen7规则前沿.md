## 五、`pareto()` 浮点比较的专项检查（队长最关心的一点）

结论：**在本次复跑中，浮点误差没有造成前沿点集抖动**。证据分三层：

### 5.1 复跑前后完全一致

- `front` 71 → 71，点集（name + cost + occ_discomfort）逐点相同，顺序也相同；
- 底层 2200 条规则的四个指标最大相对误差 0.0（不是"小于 1e-9"，是浮点值完全相同）。

原因：评估是确定性的——`SmartHomeEnv(seed=9100+ep)` 且 `env.reset(seed=9100+ep)`，`SimConfig(occupancy_mode="semi_markov")`，
8 回合 × 7 天，无 `datetime.now()` 参与状态转移。JSON 以 Python repr 全精度写出，重载得到的是同一组 float，不会引入新误差。

### 5.2 容差敏感性：不改动数据、只改判据阈值

用当前代码重新评估 680 条新规则（与既有 1520 条合并成 2200 条），然后以不同容差重算非支配集：

| `tol` | 前沿条目数 | 是否等于既有 JSON 的前沿点集 |
|---|---|---|
| 1e-9（脚本原值） | 71 | 是 |
| 1e-12 | 71 | 是 |
| 1e-6 | 71 | 是 |
| 0（严格） | 71 | 是 |

即：4 个数量级的容差变化都不改变点数与点集，前沿**不是**卡在 1e-9 边界上的"临界解"。

### 5.3 边界距离与并列结构

- 对 71 个前沿点逐个检查：**没有任何一个点存在"严格更优"的竞争者**（最紧的支配边界余量都 > 0）；
- 2200 条规则中，**没有任何非前沿点（共 2129 条）在两个目标上都与某前沿点相差 1e-9 以内**（0 条）；
  也就是说"差一点就被支配"的临界行不存在。
- 但存在大量**完全并列**：2200 条中有 12061 对规则的两个目标在 1e-12 内相等（行为相同的规则）；
  前沿 71 个条目只对应 12 个不同目标值，最多一组 21 条并列。
- 扰动实验（给 cost / occ_discomfort 加均匀噪声后重算前沿）：

| 噪声幅度 | 前沿条目数（两次试验） | 名称集合是否与基准相同 |
|---|---|---|
| 1e-15 | 71 / 71 | 相同 |
| 1e-12 | 71 / 71 | 相同 |
| 1e-9 | 25 / 18 | 不同 |
| 1e-6 | 31 / 24 | 不同 |

解释：**并列组内部谁留下取决于微小的数值差异**，所以噪声 ≥1e-9 时条目数会从 71 掉到 18~31。
但这不是"复现抖动"——实际计算里这些并列值逐位相同、可精确复现；而且在 `equal_comfort` 的插值中，
并列点在 (cost, occ_discomfort) 上完全相等，取哪一条都得到同一个 `rule_cost`，因此**不影响 RL vs 规则的对比结论**。

### 5.4 建议（不改代码，仅记录）

`pareto()` 目前不做去重，导致"前沿点数"被并列条目放大（71 vs 12）。若要报"规则能力边界的点数"，
建议在 `pareto()` 里按 (round(cost, 12), round(occ_discomfort, 12)) 去重，或至少同时在报告里给出"不同工作点数"。
这是表述口径问题，不是复现问题。
