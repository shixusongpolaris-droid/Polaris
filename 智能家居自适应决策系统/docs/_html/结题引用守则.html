一、绝对不能照抄的三个数字

1. ❌ "当前参数的全时段 RMSE 4.6138 → 拟合后 1.7790（改善 61%）"

这是错的。joint_fit_thermal.py 原先把 config 的每步值喂进按

每小时工作的拟合模型（dT 最后乘 dt=0.25），动力学慢了 4 倍，

所以"当前参数"的基线被虚高。

正确说法（同口径、同一段数据）：

参数组 全时段 RMSE 空调开 空调关 有人 无人
gen5 1.7821 1.8431 1.6925 1.8145 1.7176
gen6 1.7790 1.8722 1.6388 1.8378 1.6590

gen5 → gen6 只改善 0.17%。

因此不要写"标定大幅提升了拟合精度"。 正确的表述是：

参数在该数据上可辨识性差 —— 6 个参数变动 1.4%~17.4%，

拟合精度只提高 0.17%，但下游电量结果最多变动 32.8%。

两代参数得到的结论一致，构成一次参数不确定性下的稳健性检验。

复算脚本：scripts/compare_gen5_gen6_rmse.py

2. ❌ "规则帕累托前沿 11 点全部不被 RL 支配"

这是空真结论。rule_ceiling.py 曾被在 energy_scale_ci 结果生成之前

运行，读不到 RL 数据（rl=[]），于是"未被支配"自动等于"全部"。

正确数字（gen6 重跑后）：

RL 工作点 支配的规则前沿点数
es=10 0
es=30 0
es=60 3
es=100 6

规则前沿 11 点中，4 点不被任何 RL 工作点覆盖：

规则 电费 有人不达标
谷29/平29/峰29 关机 0.886 元 45.32%
谷26/平25/峰29 关机 1.166 元 40.53%
谷24/平24/峰24 不停机 2.815 元 0.81%
谷25/平25/峰25 不停机 2.820 元 0.00%

后两个是关键：规则的低不舒适端点 RL 根本达不到。

3. ❌ "全程开空调 25 °C 电费 5.324 元/天"

这个"元/天"其实是 kWh/天。 evaluate_all.py 用的是

RewardConfig(tou_enabled=False) 且 price_flat_tariff=1.0，

所以电费数值恒等于电量。真实分时电价下该策略约 2.726 元/天。

引用时要么写"电量 5.324 kWh/天"，要么注明"按平段 1 元/kWh 计"。

不要把它与 rules_ceiling 里的 2.820/2.373（真实 TOU 电费）放在同一张表。

二、需要限定口径的三个结论

4. ⚠️ "等舒适度下规则省 45.5% / 49.3%"

这两个数是跨 10.6 个百分点空隙的线性外推：规则前沿的

"有人不达标率"从 1.31% 直接跳到 11.92%，中间没有任何工作点。

若取保守的规则点（2.815 元，对应 0.81%）而非插值，则：

RL 有人不达标 RL 电费 保守规则点 谁的便宜
es=10 6.00% 3.813 2.815 规则省 35.5%
es=30 9.97% 3.664 2.815 规则省 30.2%

建议写法："规则在同一舒适度水平上的电费比 RL 低 30%~46%

（取决于对规则前沿空隙的取值方式）"。

5. ⚠️ "RL 不舒适下界 6.28% → 6.00%"

这是混用口径：6.28% 是全时段口径，6.00% 是有人时段口径。

同口径对比：

口径 gen5 gen6
全时段 6.28% 3.74%
有人时段 10.06% 6.00%

论文/报告里必须统一用一个口径，并在表格标题写明。
