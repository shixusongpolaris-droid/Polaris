## 三、Low

### L1（low）`_prev_compressor_on` 只在 `reset` 初始化，不在 `__init__`

- 位置：`src/env/simulator.py:667`（reset 中设 False）、`:829-831`（step 中读取）
- 事实：`HomeSimulator()` 直接 `step` 且第一步 AC 开时，`compressor_on=True` 会访问尚未存在的 `_prev_compressor_on`，抛 `AttributeError`；先 `step` 一个 AC 关的动作则因短路不会触发。正常 `SmartHomeEnv` 都先 reset，所以主路径不受影响。
- 复现：`sim=HomeSimulator(); sim.step(encode_action(1,0,0,act))` → `AttributeError: 'HomeSimulator' object has no attribute '_prev_compressor_on'`。
- 修法：在 `__init__` 中同时设 `self._prev_compressor_on=False`；或在 step 里 `getattr(self,"_prev_compressor_on",False)`。

### L2（low）`prev_ac_idx` 已不再使用

- 位置：`src/env/simulator.py:801`
- 事实：S9c 改用 `compressor_on/_prev_compressor_on` 后，`prev_ac_idx` 只被赋值，没有读取；留着会让后续维护误以为启动判断仍依赖它。
- 修法：删除，或用于 `ac_on_count` 统计。

### L3（low）`_predict_next_temp` 复制了 `_update_temperature` 的公式，存在漂移风险

- 位置：`src/env/simulator.py:473-493`（predict）与 `:495-...`（update）
- 事实：两者目前逐位一致：随机 2000 组（T 10–40、ac 0–7、vent 0/1）比较，`pred` 与 `update_temperature` 在未裁剪范围内 `maxdiff=0`；但 predict 不包含 `temp_clip_max`（有意），未来改热模型容易只改一处。
- 修法：把 dT 计算抽成 `_delta_temp(ac_setpoint, ac_on, vent_on)`，predict/update 共用；加一个“pred==update（未裁剪）”单测。

### L4（low）旧“最低功率底价”注释仍在

- 位置：`src/env/config.py:511-517`（“只有压缩机在制冷时才应用最低功率”）；`src/env/simulator.py:590-596`（“只有 gross_cooling>0 时才应用最低压缩机功率”“ac_started 表示空调从关到开”）
- 事实：当前平均功率已无 floor，启动判断已是 compressor 0→1；这些是 e9e5bb1/539561e 的旧注释。
- 修法：改为“平均功率=cooling/COP；启动=compressor 0→1；最低功率不进入平均电量”。

### L5（low）`c3_override_count`/`c3_violation_count` 只在 metrics/info，不在 episode_metrics

- 位置：`src/env/home_env.py:307-329`（`get_episode_metrics` 未包含这两个新计数）
- 事实：`simulator._new_metrics` 有 `c3_override_count`/`c3_violation_count`，`info` 每步有；但回合汇总指标不输出，训练/统计脚本看不到 C3 安全干预频率。
- 修法：把两个计数加入 `get_episode_metrics`（以及结果 JSON），并给 `test_env` 一个总数断言。

### L6（low）C4 强制关机和请求关机都把 `ac_blocked=True`
