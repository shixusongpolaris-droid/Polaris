## 2. 重点 1：实验 2 的四组是否可比（**实测**）

### 2.1 静态判断：`in_band_gradient` 只有一条通路

全仓 grep `in_band_gradient`：定义在 `config.py:409`，**唯一消费点在 `reward.py:115`**：

```
src/env/config.py:409          in_band_gradient: float = 0.05          # 定义
src/env/reward.py:115          c.in_band_gradient * c.alpha_hot * abs(temp_in - center)   # 唯一读取
```

它只进入 `temp_cost()` 的"区间内"分支 → `components["cost_temp"]` / `components["comfort_total"]` → `reward`。
而 `home_env.step()` 里唯一被指标逻辑读取的 reward 明细是 `components["temp_dev"]`：

```python
# src/env/home_env.py:262-267
m["temp_dev_sq_sum"] += float(components["temp_dev"]) ** 2
dev = float(components["temp_dev"])
if dev > 0: m["discomfort_steps"] += 1
```

`temp_dev` 在区间内恒为 `0.0`（`reward.py:115-116` 第二个返回值），**与 `in_band_gradient` 无关**。
`comfort_total` / `cost_temp` 只被写进 components；全仓唯一的读取点是 `scripts/test_env.py:205`
（奖励平衡自检，与本实验的训练/评估路径无关）。
约束层在 `simulator.step()` 的动作屏蔽里，输入只有 `ac_idx/elapsed/empty_steps`，不碰 reward。

### 2.2 实测 A：同一模型 + 同一评估种子，只换 grad

用与正式脚本**完全相同的构造路径**训练一个 64 步 PPO（`exp2.train_one(0.0, 42)`），
然后分别用 `exp2.measure(model, stats, g)`（即脚本里"每组带各自 grad 的评估环境"）跑 8 回合：

```
grad=0.00 -> energy=6.6426679168  cost=3.5451036785  discomfort=0.2408854167  occ=0.3175252112
grad=0.05 -> energy=6.6426679168  cost=3.5451036785  discomfort=0.2408854167  occ=0.3175252112
grad=0.10 -> energy=6.6426679168  cost=3.5451036785  discomfort=0.2408854167  occ=0.3175252112
三个 grad 的四个指标是否完全相等（== 逐位）: True
   energy         d(g=0 vs g=0.10) = 0.0
   cost           d(g=0 vs g=0.10) = 0.0
   discomfort     d(g=0 vs g=0.10) = 0.0
   occ_discomfort d(g=0 vs g=0.10) = 0.0
```

### 2.3 实测 B：逐位轨迹回放（排除"模型动作太单一"的偶然）

用一个只看温度/占用的确定性恒温器策略（动作与 grad 无关）各跑 672 步，只切换评估环境的 `grad`：

```
步数: 672 vs 672
温度轨迹逐位相同: True
(energy, elec_price, temp_dev) 逐位相同: True
奖励轨迹是否不同: True
回合累计奖励差 = -48.456841（grad 只改奖励，不改物理）
```

即：`grad` 确实改变了奖励（−48.46/回合，符合预期），但物理状态、每步能耗、电价、`temp_dev` **逐步完全相同**。
`cost` 与 `occ_discomfort` 由这些量算出，因此必然不受影响。

### 2.4 结论

四组**可比**。`measure()` 里用 `rew(grad)` 的写法不会造成偏差，**不需要改成统一的 grad=0 环境**。
（仍建议改为 `rew(0.0)` 并加注释，理由见 P5 —— 属于"防将来"，不是修 bug。）

## 6. 重点 5：其他常见问题（按严重程度）

### P1【中】实验 2 的 `pp` 数值印小了 100 倍（会误导读报告的人）

```python
# scripts/gen7_exp2_inband_gradient.py:231
f"电费 {dc:>+7.1%}  不达标 {dd:>+7.2f}pp  -> {verdict}")     # dd 是比例(0.03)，不是百分点
# scripts/gen7_exp2_inband_gradient.py:271
md.append(f"| {r['gradient']:.2f} | {dc:+.1%} | {dd:+.2f}pp | {verdict} |")
```

`dd = r["occ_discomfort"] - base["occ_discomfort"]` 是**比例**。实测：

```
真实差 0.0050 (=0.50pp)  ->  代码输出 +0.01pp
真实差 0.0300 (=3.00pp)  ->  代码输出 +0.03pp
```

判定逻辑本身是对的（`dd <= 0.005` = 0.5pp、`dd > 0.02` = 2pp，都用比例），所以会出现
**"不达标 +0.03pp → 判定：变差"这种自相矛盾的输出**——读者会以为脚本算错了。
而"舒适度不能明显上升"正是本实验的第二判据，这个数字会被直接引用。

修复（一行）：`{(dd*100):+.2f}pp`，或直接 `f"{dd:+.2%}"`（与其它地方的百分比写法一致）。

### P6【建议】实验 2 的"改善/变差"只用点估计，浪费了已算出的 CI

`gen7_exp2_inband_gradient.py:228-229` 用 `dc`/`dd` 的点值与固定阈值比较，
但每一臂已经算了 95% CI（`cost_ci`、`occ_ci`），且**四臂共用同一组训练种子与评估种子**（配对设计）。
建议改为按 seed 配对的差值 CI：`diffs = [r_i - base_i for i in seeds]`，再 `ci95(diffs)` 判 0 是否落在区间外。
同样的算力，功效明显更高（配对能消掉种子间方差，项目自己的记录里同配置跨种子可差 2 倍以上）。

### P7【建议】实验 1 的前沿用均值去支配，未考虑 CI

`dominated()` 只比较 `cost` 与 `occ_discomfort` 的均值。两个档位的 CI 若大量重叠，
"被支配"其实是噪声判定的。本项目其它脚本（如 `gen7_unified_protocol.py`）已引入 Welch t / 占优判据，
这里建议至少给"被支配但 CI 重叠"的行加一个"占优不显著"标记，避免把 es=20 与 es=25 这类接近点直接判死。
