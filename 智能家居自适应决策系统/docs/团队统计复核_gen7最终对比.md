# 团队统计复核 · gen7 最终对比（盲评）

- 复核对象：`scripts/gen7_final_front.py`、`scripts/gen7_dominance_compare.py` 的产物
- 原始数据：`models/gen7_rule_ceiling/results.json`（34）、`models/gen7_price_rule/results.json`（36）、`models/gen7_rule_fine/results.json`（960）、`models/gen7_rule_emptysteps/results.json`（490）、`models/gen7_final_front/results.json`、`models/gen7_vecnorm_confirm/results.json`
- 复核方式：**未阅读 `docs/` 下任何结论文档**；只读上述 JSON、`scripts/` 下 gen7 相关脚本与 `src/`；自己实现 nondominated sorting、自己重跑规则评估（不训练模型）、自己算占优/插值两套对比。
- 结论一句话：**"分工"的方向成立（低不舒适端规则更省、高不舒适端 RL 更省），但作为定量结论不成立。71 点前沿实际只有 12 个不同点；前沿混用了 12/10/8 回合三套评估；把全部规则放到同一套回合重算后，2%/5% 两档的结论会变；我构造的一条自然规则在 6.49% 不舒适率下电费 1.819 元（<1.9），使 5% 处的 RL 优势从 19% 缩到约 11%，且不再稳健显著。**

### 1.4 空档：一半是"混用回合"造成的，一半是"成本平台"

先把三个不同口径下的空档分开：

|---|---:|---|---|

| 同协议 + split + 我的 block 规则 | 12 | 6.49% → 47.59%（41.10pp） | 但 6.49% 的 1.819 与 47.59% 的 1.818 只差 0.001，成本是平的 |

- **6–9% 的规则是存在的**：新增 split 在 6.00% / 6.95% / 8.91% / 8.94% 分别给出 2.148 / 2.095 / 2.086 / 2.073 元（见 §0 的 680 条 split 网格）。

## 2. 第二步：四档占优对比的独立结果

### 2.1 复现口径

我按 `gen7_dominance_compare.py` 的定义：

```
ref(d_rl) = min{ cost(r) : r ∈ front 且 occ_discomfort(r) <= d_rl }
diff = (rl_cost - ref) / ref
t_one = (mean(per_seed cost) - ref) / (std(per_seed cost)/sqrt(10))
```

`t_one` 与队长的 t 在四舍五入误差内一致（我复算的四行：+2.88 / −1.45 / −4.63 / −10.27，对应任务给的 +2.9 / −1.5 / −4.6 / −10.3）。另外我加了 `t_welch`：把规则的逐回合标准误也算进分母（`sqrt(SE_RL² + SE_rule²)`），因为规则也是 8 回合估计，不是常数。

### 2.2 三套前沿下的四行对照

| es | RL d | RL 电费 | 发布版 ref | 发布版 diff / t | 同协议 ref | 同协议 diff / t_one / t_welch | 新规则 ref | 新规则 diff / t_one / t_welch | 新规则下 RL 种子更贵的数 |

| 10 | 1.16% | 2.795 | 2.282 | +22.5% / +2.88 | 2.282 | +22.5% / +2.88 / +2.71 | **1.916** | **+45.9% / +4.94 / +4.70** | 10/10 |
| 30 | 1.54% | 2.084 | 2.183 | −4.5% / −1.45 | 2.282 | **−8.7% / −2.91 / −2.11** | **1.916** | **+8.8% / +2.48 / +1.89** | 8/10 |
| 60 | 5.02% | 1.660 | 2.056 | −19.2% / −4.63 | 2.181 | **−23.9% / −6.09 / −5.26** | **1.863** | **−10.9% / −2.37 / −1.91** | 3/10 |
| 100 | 8.70% | 1.505 | 2.056 | −26.8% / −10.27 | 2.181 | **−31.0% / −12.60 / −9.23** | **1.819** | **−17.3% / −5.85 / −4.14** | 0/10 |

（"新规则"= 同协议 1520 条 + split + 我构造的 block/custom 规则，见 §3；"RL 种子更贵的数"= 10 个训练种子里电费高于参照规则的个数。）

### 2.3 逐行判断：是否支持队长给的四行？

**es=10（1.16%）——方向支持，但幅度被低估。**

- 发布版 +22.5% / t=+2.88，我复算完全一致；同协议也是 +22.5%（因为参照点来自 9100，未受混用影响）。
- 但发布版规则族漏掉了一条更便宜的 0.98% 规则（B7，1.916 元，见 §3）；用它做参照，RL 贵 **+45.9%**，t=+4.94，**10/10 个 RL 种子都比规则贵**。所以"规则在 1–2% 更省 22.5%"不仅成立，而且**低估了规则的优势**；真实优势约 46%。

**es=30（1.54%）——不支持"持平"。**

- 发布版 −4.5% / t=−1.45 的参照 2.183 来自 **9900** 回合；同协议 9100 下同一条规则是 **2.282 / 0.98%**，于是 RL 便宜 **−8.7%**，t_one=−2.91（过 2.262），t_welch=−2.11（在 5% 临界 2.1–2.26 的边缘）。
- 再把 §3 的 1.916 规则放进来，参照变成 1.916，RL 反而贵 **+8.8%**，t_one=+2.48、t_welch=+1.89。
- 也就是说：**2% 附近不是"持平"，而是"符号会随规则族翻转、显著性在边缘"**。发布版的 −4.5%/不显著是混用回合 + 不完整规则族的产物，不能作为"持平"的证据。

**es=60（5.02%）——方向支持，但"19.2% 显著"不稳。**

- 发布版 −19.2% / t=−4.63 的参照 2.056 也来自 **9900**；同协议 9100 下是 2.181，RL 便宜 **−23.9%**，t_one=−6.09、t_welch=−5.26。
- 但把 §3 的 2.70% 规则 B6（1.863）放进来，参照降到 1.863（B1 在 6.49%，高于 es60 的 5.02%，不参与 es60 的参照），RL 只便宜 **−10.9%**，t_one=−2.37、t_welch=−1.91；**3/10 个 RL 种子比规则还贵**。
- 所以"RL 在 5% 更省 19.2%（显著）"不是稳健结论：**幅度在 11%–24% 之间随规则族变化，显著性在 Welch 口径下不过线**。

**es=100（8.70%）——方向支持，但"26.8%"高估。**

- 发布版 −26.8% / t=−10.27 的参照 2.056 仍是 9900；同协议 2.181 给 −31.0%，t=−12.60/−9.23。
- 新规则 1.819 给 **−17.3%**，t=−5.85/−4.14，0/10 个种子比规则贵。**方向稳健（RL 更省），但 26.8% 高估了；更合理的量级是 17% 左右。**

**小结：四行里只有 es=10 的"参照 + 方向"被支持；es=30 的"持平"不被支持；es=60 的方向支持但幅度/显著性不稳；es=100 的方向支持但幅度被高估。**

## 3. 第三步：判据本身，以及我构造的规则

### 3.1 "不舒适率不高于 RL 的规则中最便宜者"对谁有利？

**对 RL 有利。** 因为参照规则要求 `d_rule ≤ d_rl`，它通常比 RL **更舒适**，而更舒适通常更贵；用它的电费当参照，等于让规则背一个"舒适溢价"，于是：

- RL 更贵时（es=10/30），参照越高，RL 的"贵"看起来越小；
- RL 更便宜时（es=60/100），参照越高，RL 的"便宜"看起来越大。

脚本 docstring 说这个判据"不会冤枉 RL"——这正是它的偏向：它把"规则可以更舒适"的成本算进参照，系统性地让 RL 显得更好。**中性的等舒适度比较应该在 `d = d_rl` 处插值**，而不是取一个更舒适的点。

数值上，这个偏向在本数据里不大（因为前沿在空档内几乎是平的）：

| es | 发布版 step ref | 发布版 interp ref | 差异 |
|---:|---:|---:|---:|
| 10 | 2.282 | 2.231 | +2.3% |
| 30 | 2.183 | 2.182 | +0.05% |
| 60 | 2.056 | 2.054 | +0.1% |
| 100 | 2.056 | 2.051 | +0.25% |

新规则前沿下差异更小（es=60：1.863 vs 1.854，约 0.5%）。**所以"占优 vs 插值"不是本次结论翻转的主因；主因是规则族遗漏和混用回合。** 但把"占优判据"说成"更保守、不会冤枉 RL"是不准确的——它是有方向的偏向，只是本题里数值小。

另一个相反方向的偏差：`ref = min{...}` 是在几十条近似并列的规则里取最小值，**规则侧有 winner's curse（偏乐观）**，这会让 RL 显得更差。两个偏差方向相反，净效应不能先验判断；这也是为什么"占优判据"不能当作无偏基准。

### 3.2 t 统计量：不是 Welch，且忽略了规则侧不确定性

`gen7_dominance_compare.py` 的 `t` 是：

```
t = (mean(RL per-seed cost) - ref_cost) / (std(RL per-seed cost)/sqrt(10))
```

这是**单样本 t（把规则当成常数）**，不是 Welch 两样本 t；它忽略了：

1. 规则自身 8 回合的抽样误差（`SE_rule`）；
2. 参照规则是从几十条里选出来的（选择偏差）；
3. RL 与规则共用 9100–9107 回合（配对结构），但只用了 RL 的种子间方差。

我加的 `t_welch` 把 `SE_rule` 放进分母；这会让 |t| 缩小约 5–25%，在边缘档（es=30、es=60）直接改变显著性判断：

| es | 发布 t_one | 同协议 t_one / t_welch | 新规则 t_one / t_welch |
|---:|---:|---|---|
| 10 | +2.88 | +2.88 / +2.71 | +4.94 / +4.70 |
| 30 | −1.45 | −2.91 / −2.11 | +2.48 / +1.89 |
| 60 | −4.63 | −6.09 / −5.26 | −2.37 / −1.91 |
| 100 | −10.27 | −12.60 / −9.23 | −5.85 / −4.14 |

另外，脚本用 `|t| > 2.0` 判显著，而 5% 双侧、df=9 的临界值是 **2.262**；新规则下 es=30/60 的 `t_one` 为 **2.48 / 2.37**（刚过 2.262），但 `t_welch` 为 **1.89 / 1.91**（不过 2.0）——**结论取决于用哪个检验**。所以这两档的"显著"是脆弱的，不能作为强结论。

## 5. 异常与矛盾清单

1. **71 是重复计数，不是 71 个点。** 唯一 (cost, d) 点只有 12 个；59 条是并列重复；`in_band_1_10` 的 29 条只有 3 个不同点。`pareto()` 不去重是直接原因。
2. **前沿混用 12/10/8 回合三套评估。** fine/empty/split 用 9100，price 用 9900，ceiling 用 9600；发布版的 2.183/1.33 与 2.056/2.64 是同协议不存在的 9900 版本；同协议下它们退化为 2.282/0.98 与 2.181/2.23。
3. **"空档是基线缺陷"只对了一半。** 6–9% 的规则存在（新增 split 在 6.00/6.95/8.91/8.94% 有工作点）；在发布版混用前沿里它们被 2.056（9900）支配，所以进不了 `front`。但在同协议 9100 下 2.056 不存在（它是 2.181/2.23），split 点会进入前沿，空档从 30.8pp 缩到 **25.5pp（8.94–34.40）**。所以空档的一半是"混用回合"造成的，另一半（9–34%）才是成本平台。**不是"规则族不存在 6–9% 规则"，也不是"新增 split 规则本身把空档填上了"——是统一回合后它们才进入前沿。**
4. **任务说 612 条新规则，脚本实际 680 条。** `17 × 4 × 5 × 2 = 680`；`n_rules=2200`。这个数字差异不影响结论，但说明任务描述与产物不一致。
5. **`gen7_final_front.py` 的 docstring 说 `gen7_price_rule` 24 组，JSON 有 36 组；`gen7_final_front` 的 docstring 也有过期描述。** 属于文字与实现不一致，不是计算错误。
6. **`t` 不是 Welch。** 单样本 t 把规则当常数，忽略规则 8 回合的 SE 和"min over rules"的选择偏差；`|t|>2.0` 比 df=9 的 2.262 宽松。边缘档（es=30/60）的显著性因此不稳。
7. **占优判据对 RL 有利。** 参照规则通常比 RL 更舒适，其成本含舒适溢价；这与"不会冤枉 RL"的自我描述一致，说明它是有方向的偏向。数值上小（≤2.3%），但方向上不能称为中性。
8. **发布版 `results.json` 的 `equal_comfort` 与 `dominance.json` 不是同一口径。** 前者是插值（es=10 rule_cost 2.231，t=3.17），后者是占优（2.282，t=2.88）；任务引的是后者。两个文件并存容易误读。
9. **规则参照取 min over 几十条近似并列，存在 winner's curse。** 规则侧成本偏乐观，方向与第 7 条相反；两个偏差的净效应无法先验判断。
10. **8 回合不是 8 个独立场景。** 都是 2026-01-05 起的同一周、同一 TOU、同一 `lookahead=0.6`；跨回合只能测噪声，不能外推到其他季节/户型。这一点在之前的复核里已经出现过，gen7 仍然如此。
11. **B1–B7 是后验搜索出来的。** 跨 9200/9600/9900 的成本/舒适度区域稳定（1.70–1.93，0.6–7.7%），说明方向真实；但"best-of-search"仍乐观，不能把 1.819 当作无偏的规则上限。
12. **规则前沿的高不舒适端点也在变。** 同协议下 2.033/32.33 → 2.068/34.40、1.958/35.83 → 1.983/37.37、1.817/45.30 → 1.840/47.29、1.796/45.54 → 1.818/47.59；发布版高不舒适端的"规则更便宜"也被混用回合放大了约 0.02–0.04 元。

## 6. 总判定

**"分工"这个结论：方向成立，定量不成立。**

- **低不舒适端（1–2%）**：规则更省，发布版 22.5% 是**低估**；用 B7（1.916/0.98）参照，优势约 **46%**，10/10 个 RL 种子都比规则贵。**这一条强成立，且比发布版更强。**（B6/B1 在更高的 2.70%/6.49% 档，分别给出 5%/9% 档的参照，见 §2。）
- **2% 附近**：**不是"持平"**。同协议下 RL 便宜 8.7%（t_one −2.91，t_welch −2.11）；加入自然规则后规则便宜 8.8%（t_one +2.48，t_welch +1.89）。**符号随规则族翻转，显著性在边缘；不能写成"持平"。**
- **5% 附近**：RL 更省的方向成立，但发布版 19.2% 不稳；同协议 23.9%，加入自然规则后 **10.9%**（t_one −2.37，t_welch −1.91），**3/10 个 RL 种子比规则还贵**。**"19–27% 显著"不成立；更合理的量级是 11–24%，且 5% 处不稳健。**
- **9% 附近**：RL 更省的方向成立，但发布版 26.8% 高估；同协议 31.0%，加入自然规则后 **17.3%**（t_one −5.85，t_welch −4.14），0/10 个种子更贵。**方向稳健，幅度约 17%。**

**限定条件**：如果"分工"只声称"在这 2200 条规则的网格里"，那么 71/12 点、2.056/2.183 等是网格内的真实值；但它不是"规则范式"的上限——网格缺了"小时 block"和"滞环宽度"两个自然维度，补上后 5% 的 RL 优势从 19% 掉到 11%。作为"规则 vs RL"的一般结论，它不成立；作为"这个网格 vs RL"的结论，也至少要把 2% 和 5% 改成"不显著/边缘"，不能写成"持平"和"显著 19–27%"。

如果只允许保留一句话：

> **"规则在低不舒适端更省、RL 在高不舒适端更省"这个方向是对的；但"2% 持平"和"5–9% RL 显著省 19–27%"是混用回合 + 不完整规则族的产物。把规则放到同一套回合、并补上"小时 block + 滞环宽度"这类自然规则后，低端规则优势更大（~46%），中端 5% 的 RL 优势只剩 ~11% 且不稳健显著，9% 的 RL 优势约 17%。**
