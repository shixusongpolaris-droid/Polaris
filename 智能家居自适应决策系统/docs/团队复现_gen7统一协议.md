## 四、`welch_t()` 代码审查（重点）

### 4.1 公式判断：**当前实现是正确的**

```python
va = stdev(a) ** 2 / len(a)
vb = stdev(b_all) ** 2 / len(b_all)
se = math.sqrt(va + vb)
t = (mean(a) - b_mean) / se
```

- `statistics.stdev()` 是**样本标准差（ddof=1）**，所以 `stdev(a)**2` 就是样本方差 s²；
- 标准误的平方是 **s²/n**，因此 `va = s²/n`、`vb = s²/n`、`se = sqrt(s1²/n1 + s2²/n2)`；
- 这正是 Welch t 统计量 `t = (x̄1 − x̄2) / sqrt(s1²/n1 + s2²/n2)`（不合并方差）的定义。

**队长设想的 `s²/(n−1)` 不是标准误**：那会把 SE 放大 `sqrt(n/(n−1))` 倍（n=8 时 1.069、n=10 时 1.054），
从而把 |t| **缩小**约 5%~6%。也就是说，若按该设想改，结论只会变得**更不显著**，不是修正。

### 4.2 与 scipy 的独立对照

用 `scipy.stats.ttest_ind(..., equal_var=False)`（标准 Welch）对照，4 行全部吻合：

|---|---|---|---|---|---|

### 4.3 三种方差口径的对比（是否影响判断）

| es | 当前（s²/n，正确） | 队长设想（s²/(n−1)） | 总体方差（ddof=0） | |t|>2 判定是否翻转 |
|---|---|---|---|---|
| 10 | +4.6073 | +4.3653 | +4.8625 | 否 |

若用 `s²/(n−1)`：0.0012 / 0.1300 / 0.0477 / 0.0023 —— 没有任何一行的显著性结论翻转。

### 4.4 统计口径注记（不是代码缺陷，但影响 t 的解读）

1. **两侧样本的统计单位不同**：
   - RL 侧 10 个值 = 10 个训练种子的**模型均值**，每个模型都在**同一批 8 个评估回合**（9100~9107）上取平均；
   - 规则侧 8 个值 = **逐回合**电费。
   因此两侧并非独立样本（共享同 8 个评估回合），且方差含义不同（训练种子间变异 vs 回合间变异）。
   严格做法应是配对检验（按回合配对），但 JSON 只存了 RL 的模型均值、未存逐回合值，无法从产物里做配对检验。
2. **方差主要来自 RL 侧**：SE² 中 RL 侧占比 es=10 为 91.1%、es=30 为 59.8%、es=60 为 68.4%、es=100 为 45.2%。
   即这个 t 主要度量的是"训练种子间波动"，而不是"评估回合间波动"。
3. **插值参照的 t 是近似**：插值点的电费是相邻两点线性插值出来的，没有自己的逐回合样本；
   代码退化为借用**下邻点**的 `cost_all`。我核对了该分支：存储的 `int_t`（+4.6259 / +1.8152 / −2.1644 / −3.8284）
   与"用下邻点方差"重算完全一致；若改用上邻点方差，t 分别变为 +4.566 / +1.716 / −2.149 / −4.093，量级不变。
4. **多重比较未校正**：一张表里 4 个 scale，es=60 的 p=0.037 属边缘显著（换成 s²/(n−1) 则 p=0.048），
   在 4 次比较下不宜按 0.05 直接下结论。
5. 脚本本身只**报告** t、没有用 |t|>2 做判定（JSON 无 `sig` 字段），所以即便口径有争议，代码里也没有"自动下结论"的开关。

**小结：`welch_t()` 无公式错误；上述 1~4 是使用该 t 值时的解释边界。**

## 八、局限

- 只验证"同机、同解释器、同依赖版本、同一份数据"下的复现；跨机器 / 跨 BLAS 未验证。
- RL 侧 `per_seed` 是既有产物 `models/gen7_vecnorm_confirm/results.json`（本次未重训，也不在任务范围）。
  本审计验证的是"用这些既有 RL 结果重算对比是否一致"，不是"RL 模型能否复现"。
- 规则侧与 RL 侧的配对结构（同 8 个评估回合、不同统计单位）无法从现有 JSON 还原逐回合配对样本，
  因此只能给出 Welch t 的近似 p 值，不能给出严格的配对检验。
- 未评估"规则族是否覆盖了足够的规则空间"这类建模问题——本任务只审可复现性与代码正确性。
